# RX 7900 XTX 八图社区案例核对

来源：用户于 2026-10-15 提供的同组八张图和正文。以下吞吐和增益均为作者报告，未取得原始日志和完整可执行配置。作者未明确给出引擎版本/hash、请求内容、重复次数及全量内存分配信息。

## 平台和数据

- RX 7900 XTX 24GB；双 Xeon E5-2680 v4、56逻辑线程、无AVX-512；62GB DDR4；Ubuntu、ROCm7.2.4。
- SC117 abliterated IQ3_XXS / Q2_0，主 prefill 曲线是 IQ3_XXS，并非本机 Swift IQ3_S。
- max-context262144、KV int8、MTP、vision、prefill auto；另报告 AUTO_MAX32768 和 HIP 专用环境变量。

| 输入标称长度 | prefill tok/s |
|---|---:|
| 4K | 685.5 |
| 16K | 1566.5 |
| 32K | 1831.2 |
| 64K | 2030.0 |
| 128K | 1812.0 |
| 240K | 1621.9 |

IQ3_XXS decode64–78，Q2_0 decode60–83；作者报告 MTP 接受率49–69%。峰值之后 prefill 下降，说明增长并非必须单调。

## 可参考的机制

1. 固定512 chunk可能使矩阵批量偏小、反复流入专家权重及kernel/synchronization等成本占比很高；更大chunk能够摊薄成本。不过不能把所有专家缓存借出/归还都认定发生在每个chunk，需核对具体实现。双卡还涉及流水重叠、借槽数量与RAM副本，并非chunk越大越快。
2. RAM专家副本可减少运行期间文件访问和缺页；本机已有RAM预算/arena机制，不能只凭没有mmap-experts参数认定全部专家已锁页驻留。
3. 图中 STRATA_HIP_PROMPT_F16 / STRATA_HIP_WMMA 为AMD路径，不用于本机CUDA。BF16_TC也不能视为完全等效开关。
4. STRATA_IO_THREADS 对PLE文件读取可能有帮助；本机PLE为ram路径，不能迁移作者的7%增益。

## 需纠正的推断

- “2030是官方同卡901–966的2.1倍”：引用官方测量点实际为4210和8830token的热身后新prompt、零KV复用，并非64K；旧版本、不同CPU和配置。算术比值成立，匹配条件下的提升结论不成立。
- “262K不要钱，KV不随上下文增长”：GDN状态固定不代表混合架构里的QSA KV固定。官方说明有KV streaming及随上下文增加的RAM占用。8MB显存差异可能由预分配、KV转移到RAM、expert-cache auto重分预算或只核对max-context加载状态造成，现有截图无法判定。
- “MMQ重编译无增益因为CPU无AVX-512”：单凭这两点不能定位瓶颈。还需确认内核实际启用、CPU专家耗时、PLE、专家数据搬运和GPU等待；编译成功不等于请求走了新内核。
- 20题零拒答、能读图不构成BFCL/数学/长上下文可靠性的量化验收，great/good标签不是通用分数。
- 各项提升缺少相同基线/顺序记录，不能相加或相乘推算本机最终增益。

## 对本机的行动含义

已测试auto、auto:16384等，不具备从512恢复到合理chunk的相同起点，因此不预期复制5–7倍增益。保持既定先测带宽、再测Swift单请求长输入的安排；应额外从现有/后续日志核对实际chunk、RAM副本/锁页、借出槽位的副本覆盖及读文件/实际磁盘字节。后续若仍需试更大chunk，先看有无卡在上限，再选择单一代表长度验证，不直接全局追加32768。

本次只分析和归档，未运行性能测试或调整服务器。
