## 截图中的证据

作者初始使用 IQ3_S、prefill auto:32768、spec 4、spec-min-p 0.5、KV int8/resident32768、vision、显存预留700、会话缓存20000 MiB/8槽。另一回复者建议 pcie-frac=1、spec-min-p=0.7。

最初随机负载/监控面板观察为 decode +12%、prefill 降到不足2000；后续作者改用官方 bench，确认 prefill 基本不受影响，两个值调高也未更优。

## 上游核实

- 当前部署版本 v0.1.43.1 的官方 DETAILS.md：pcie-frac 设置显存未命中专家中交给 GPU 处理的比例，其余由 CPU 处理；单卡的新自动校准不用于 layer split、batch、peer GPU。手动设置优先。calibrate 以输出速度选参数，不是完整长上下文 prefill 诊断。
  https://github.com/Niko1221/Strata/blob/v0.1.43.1/docs/DETAILS.md
- PR #1737 优化的是 STRATA_ROUTE_RESIDENT 的 swap kernel。维护者确认已 cherry-pick 到 0.1.43，GitHub 显示 closed 并不表示未收录。补丁相对于原有 route-resident 实现保留行为；开启 route-resident 相对于关闭会改变专家路由，论文式小样本质量测量不能替代 BFCL 验收。并非无损 prefill 加速。
  https://github.com/Niko1221/Strata/pull/1737
- MULTI_GPU.md 说明 prefill 借用专家缓存槽位、保留 RAM 副本和 streamed ring 的关系，以及缺少 RAM 副本时每个 chunk 回读模型文件的案例。该文档 main 内容随上游变动，只能作为本机观测的检查方向，不能据此认定当前二进制包含新修复。
  https://github.com/Niko1221/Strata/blob/main/docs/MULTI_GPU.md

## 本机参考顺序

1. 保留已讨论的内存带宽测量，以及 Swift IQ3 单请求、相同长输入、数数/正常任务配对；记录引擎与客户端各自的耗时、实际 MTP 接受率和专家数据来源。
2. 排查 prefill 时，重点看借出槽位对应的 RAM 副本、文件读取量、实际磁盘读取量、NUMA 和每 chunk 时间。文件层读取不等于实际 SSD 读取，需同时观察进程 read_bytes。
3. pcie-frac / spec-min-p 留作 decode 后续小范围对照；不直接照抄1/0.7，不运行大矩阵校准覆盖现有配置。
4. Windows large pages 的建议不能等同于 Linux 内存锁页，也不能直接推出 PVE hugepages 有收益。
5. PR1737 不列为当前 prefill 待优化项，保持 route-resident 未启用。

本次只阅读、核实和归档，未更改服务参数、启用大页、编译补丁或启动性能测试。
