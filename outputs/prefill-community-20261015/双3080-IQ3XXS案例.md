# 百川东到海ofp：双3080 / IQ3_XXS案例

来源：用户2026-10-15提供的正文和参数图。社区实测摘要，未取得固定版本、完整配置、原始请求、重复轮次和逐请求日志。无本机配置变更。

## 作者报告

双RTX3080 20GB、双E5-2696v3、96GB DDR4-2133、IQ3_XXS。生成90–99tok/s、峰值120；prefill1400–1800；MTP接受率90%+；专家命中95–99%。262144是配置窗口，文字中的26万字并非精确token计数。

参数片段：expert-cache auto、prefill auto:32768、spec6、spec-min-p0.5、mtp rt、max-context262144、kv k8v4、mtp-q4 proj、layer-split auto。没有列出kv-resident、hnorm、CPU线程/亲和和是否关闭尾部跳过等。

作者报告layer-split56→99；pipeline-windows2为95→83、占用284MiB cache；lookup-chain在1129窗口中零采纳；ple-io ram因memlock限制失败。

## 核对与判断

1. layer split无需NVLink可以运行，与本机路径一致。单卡到双卡增加专家缓存及改变计算分工，收益不能视为任意双卡固定增益。56→99按算术约+76.8%，不是图中的+60%；“三倍”也缺少对应基线。
2. pipeline2本身新增验证窗口/状态快照，消耗专家缓存；命中与猜测成功情况决定净收益。官方明确两阶段并非普遍加速。本机单流课本single-default69.7、pipeline2为66.0，已有相同方向的观察；pipeline2双客户端聚合34.14/34.81胜batch28.03/28.37属于另一个比较，不能混用。
3. K8V4是K8bit、V4bit，官方说明比int8节省约23%KV内存。与fp16相比的816/2048字节不能代表相对本机int8的节省比例。本机KV驻留32768，显存收益应针对驻留部分而非整段262K；KV量化改变精度，需长输入验收。
4. 官方v0.1.43.1的mtp.cpp先cudaMalloc原dense_，随后make_q4_dense再cudaMalloc dense4_，并vram_+=total；原dense_在析构释放。proj并非直接释放原Q8显存。本地阅读副本mtp-v01431.cpp。作者若用不同版本可能不同，不能以此断言其速度数据无效，但“省显存给expert cache”尚无依据。
5. lookup-chain依赖复用/匹配的输出内容，零采纳支持该负载下不启用，不代表代码复制编辑任务一律无收益。
6. spec6的收益取决于草稿实际接受深度与验证成本；总体接受率高不能证明6胜4。本机保持spec4。
7. LimitMEMLOCK是锁页准入限制，设无限不创造物理RAM，也不消除NUMA/PCIe代价。容器另有memlock限制时要一起核对。本机已经PLE ram，不照搬他的失败结论。
