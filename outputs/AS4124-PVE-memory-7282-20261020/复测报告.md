# AS4124 换回双路 AMD EPYC 7282 后的内存带宽复测

测试时间：2026-10-20T11:12:54.608683 至 2026-10-20T11:13:36.337255（Asia/Shanghai）。

## 结论

供电不齐时单路约7–8GB/s的严重低带宽没有重现。核对NUMA落点后，双路7282纯读取中位数115.08GB/s，两路分别57.33、57.83GB/s。四个电源均为ok；系统识别2颗7282、每颗16物理核心、共64逻辑CPU，内存约256GB。

## 纯读取：LIKWID 5.2.2 load_avx

这里每路以物理核心而非SMT线程执行。新LIKWID工作集每路1024MB（十进制），旧结果为1536MB；测试二进制SHA256一致，循环16轮。节点1另用原1536MB工作集复核，中位数58.60GB/s，与本次1024MB的57.83GB/s接近。不能把表中差异全归因于CPU：工作集、后台负载与可用本地内存不同。

7452使用全部32核心/路时的历史双路读取为140.95GB/s；那是64个物理核心与本次32物理核心的不同测法，不作为同线程数直接对照。

## 为什么补了第二轮

第一轮虽然线程落点正确，但节点0空闲内存紧张，LIKWID进程峰值采样约56%的页落在节点1；双路页比例约28%/72%。因此第一轮节点0约45.86GB/s、双路77.48GB/s不用于“本地带宽”的正式结论。原始数据保留于raw/。

第二轮在单路读取命令外加numactl --membind=0或1，双路加--membind=0,1并继续使用独立本地工作组；核对实际工作CPU。首遍每项采样的全进程页比例：节点0读取99.80%本地、节点1读取99.72%本地，双路49.65%/50.35%。这些比例包括程序及共享库页面，不仅是数组。单路STREAM也核对近100%本地。第二轮数据位于raw-local/。

## 运行条件与核验

- 虚拟机保持运行；CPU0物理核0–15，CPU1物理核16–31，SMT对应32–63。只设置基准子进程的CPU和内存亲和性。
- 第二轮24个基准进程正常退出，12次STREAM数值校验通过；虚拟机列表前后一致；PVE boot ID未变化。
