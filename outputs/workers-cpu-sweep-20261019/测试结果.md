# Strata CPU 参与线程数测试（2026-10-19）

状态：completed；模型 sc117 IQ3_S + Q8 PLE，Strata 0.1.45。

## 结果解读

本轮没有观察到从 8 增至 16 或 24 个参与线程带来明显收益。简单任务解码中位数为 128.1 / 125.2 / 126.0 tok/s；复杂任务为 70.7 / 70.9 / 70.2 tok/s。240K 首 token 时间均约 111 秒，预填充也没有随线程数明显改善。

在本轮测过的范围内，8 个参与线程已接近最好表现，可把 7 workers + 主线程作为后续候选。本次按计划恢复原来的 15 workers。虚拟机始终为 32 vCPU，因此不能据此断言把虚拟机直接缩到 8 vCPU 也不会变慢；辅助线程可用 CPU 和虚拟机内外调度仍会变化。

当前为双 RTX 2080 Ti 推理、2070 SUPER 负责视觉的配置。后端专家缓存命中率约 96%–99%，这组结果支持“当前配置下增加 expert pool 线程不是主要提速手段”。它不能单独量化 Zen 3 IPC 收益，也不能直接决定 7443 与 7452 的差价是否值得；IPC、GPU、功耗限制、NUMA 和显存缓存配置都没有做独立对照。

三组开始时 expert_slots=17152、expert_slots_primary=8890、spec=6、mtp_max=4、prefill_cap=8192、prefill_stages=2，除 pool_workers 外这些已核对的引擎参数一致。16/24 线程组运行中的 nvidia-smi 快照显示两张推理卡功耗上限均为 180W，热降频计数为 0；未调整功耗设置。

每项只测一次，数个百分点的差别不足以证明某一档稳定更快；尤其复杂文本的 MTP 接受率不同。后续若继续优化，按原计划另做亲和性/NUMA 对照，再评估虚拟机 vCPU 配额。

EvalScope Perf，单并发、流式，每项仅一次，输出上限 1000 tokens，reasoning_effort=none。每组独立重启引擎，短请求和约 32K 请求预热不计入成绩。所有正式请求检查前缀复用为 0。
