# Strata 15 workers 绑核对照结果

测试于 2026-10-13 23:05 后执行。使用同一课本、预热和三个正式问题，每题重复 3 次。模型、采样、输出目标、cache reuse 策略与不绑核组一致：Strata 0.1.43.1，15 pool workers，`pcie_frac=0.28`，layer split 27（CUDA0 层 0–26，CUDA1 层 27–47），每次目标约 3000 字、上限 6000 tokens。

### 绑核方式

Strata 主线程运行在 guest CPU 0，15 个 pool workers 分别固定在 guest CPU 1–15。PVE 上 VM vCPU 0–15 分别固定到宿主机物理 CPU 0–15；这 16 个 CPU 属于显卡所在的 socket 0，每个对应一个独立物理核心。guest 线程映射和 PVE 亲和性均在测试前后核实。VM 其余 20 个 vCPU 及 QEMU 辅助线程仍保持 `0–63` 可调度。

### 同题同轮配对

### 结论

本轮没有看到明显的绑核提速：decode 中位数约低 1.0%，同题配对中位变化约低 2.2%，9 个配对中 7 个略慢、2 个略快；变化范围为 −5.2% 至 +2.4%。首 token 等待约快 0.10 秒，属于很小的差异。绑核组的请求间 CV 为 4.0%，低于不绑核池的 5.4%，但两组样本量和测试时段并不相同，不能据此认定波动显著改善。

回答阶段的一秒监测样本中，绑核组 VM CPU 均值 41.4%、双卡 GPU 利用率 46.1%、双卡合计功耗 295.5 W；不绑核前后两组 CPU 均值约 41.2% / 41.5%、双卡 GPU 利用率约 46.0% / 45.6%、功耗约 299.4 / 296.3 W。监测值整体相近。

因此这组结果不支持把该绑核设置长期保留为提速优化，也没有触发明显差异时再补一组的条件。结论限于本次 15-worker、双卡和当前模型配置。
