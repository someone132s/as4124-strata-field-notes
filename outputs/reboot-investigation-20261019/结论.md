# AS4124 异常重启调查（2026-10-19）

采集时间：2026-10-19 12:09–12:11，Asia/Shanghai。所有远端操作均为只读；未启动核心数测试、内存测试、修改配置或主动重启服务。

## 结论

AS4124 宿主机发生了连续异常重启。最直接的证据是两次启动均通过 BERT 读到了上次启动遗留的致命处理器错误，重复定位到 socket 0、core 11。逻辑 CPU 11 和 75 是该物理核心的两个 SMT 线程，并非两颗 CPU 分别报错。

这强烈支持 CPU 核心/缓存路径的硬件错误导致整机异常重启；尚不能凭日志判定 CPU 芯片永久损坏，也不能区分 CPU 本体、插座安装接触、主板供电瞬态和固件设置。

## 错误原文与定位

两次启动后的记录均包括：

```text
BERT: Error records from previous boot:
event severity: fatal
fru_text: ProcessorError
Local APIC_ID: 0x16
Error Structure Type: cache error
Operation: 3, data read
Level: 1
Processor Context Corrupt: true
Uncorrected: true
Overflow: true
CPU 11: Machine Check: 0 Bank 0: fea04000000c0135
SOCKET 0 APIC 16
CPU 75: Machine Check: 0 Bank 0: dc204000000c0135
SOCKET 0 APIC 17
```

原始日志存在并发输出穿插；以上为保留字段的节选。APIC 16/17 为内核该字段的十六进制表示，与 BERT 的 0x16/0x17 对应。

主机拓扑确认：CPU 11 和 75 均在 socket 0、core 11，thread_siblings_list 均为 11,75。两颗处理器的 DMI 型号均为 EPYC 7452。

## 其他观察与证据边界

- 本轮正式测试没有启动：本地没有 sweep.json；配置日志仍为 pool-workers=15；远端未发现测试进程。准备阶段执行过短冒烟请求，不能表述为完全没有发过请求。
- 原有 NVMe/PCIe AER 仍有 corrected 记录，aer_uncor_status=0。当前直接导致怀疑的证据是另外的 fatal ProcessorError，不能把 corrected AER 当成已经证实的重启原因。
- 故障前最近 CPU 温度记录约 43–44°C；当前 CPU 和 VRM 温度读数无超温提示。这降低持续过热的嫌疑，不能排除未被采样的瞬时事件。
- 当前 PS1–PS4 均显示 Presence detected，chassis status 无当前 Main Power Fault。存在状态不等于已验证四路实际输出稳定。
- 当前 EDAC mc0/mc1 的 ce_count 和 ue_count 均为 0；这些是本次启动计数，不能排除此前内存错误。
- 当前 BMC 硬件 watchdog 为 Stopped；HA 资源配置文件不存在，已检查范围内未见 fencing 触发记录。不能仅凭当前状态回推重启前全部状态。
- /sys/fs/pstore 为空，无 /var/crash。没有取得故障瞬间的完整内核转储。
- BMC 时钟显示 2026-04-27，而操作系统为 2026-10-19。SEL 仍在新增，不能把日期为 4 月的日志简单视作陈旧记录；本次保留原时钟，未校时或清日志。
- 集群 Quorate=Yes；原运行中的虚拟机已随开机自动启动，Strata 已恢复 healthy。恢复在线不能证明硬件已稳定。
