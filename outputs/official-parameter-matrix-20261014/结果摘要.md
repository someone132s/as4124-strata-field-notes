# Strata 官方参数对照：ring、prefill、aux-cpus

测试日期：2026-10-14 至 2026-10-15。所有组使用 Strata `0.1.43.1` 官方 `tools/strata_bench.py`，`--runs 3 --clients 2`。模型为 `swift-1.5-abliterated-iq3_s-q8ple`，上下文 262,144；workers 15、parallel 2、batch-groups 1、batch-mtp、layer-split auto、`--mtp-hnorm stream`、KV int8 / resident 32768，以及两卡预留 550/600 MiB 都保持一致。对照基线是先前的 hnorm-stream 官方报告；四组各自完整重启后测试。

每个实验组的 chat、prompt、agent 与并发子测试均通过，报告中无 failed 或 skipped 项。

## 解读

- 目前最值得单独保留为候选的是 `--aux-cpus auto`：fresh 4K/16K prompt 都有改善，首 token 时间也更短；代价是 agent decode 慢约 6.7%，双并发总吞吐低约 3%。这是偏向长 prompt 的取舍，不是全面加速。
- 单独把 prompt chunk 提到 16K 在本机没有获益：4K 和 16K prompt 都变慢，16K 约慢 28%；双并发和 agent decode 基本持平。
- ring 384 的结果偏混合：4K prompt 有改善，16K 略退；两并发测得提升较大，但只有三轮且跨时间对比，不能把 +21.4% 当作稳定因果收益。
- 三项同时开启没有叠加出收益：16K prompt 比基线慢约 21%，agent decode 慢约 4.8%，双并发慢约 6%。当前没有理由用组合配置。
- Chat decode 的各组中位数都比基线高，但首轮请求常明显偏慢，测试期间波动很大；这些短 chat 值不适合用来单独判定微调效果。

## 限制和显存观察

这是三轮重复的定性基准，不是严格的交错 A/B/A 测试；每组都重新加载模型，基线报告也来自更早的一次运行。GPU/主机缓存、启动后的热身和运行时波动都可能影响组间差异。优先相信一致出现的长 prompt 指标，不要把小幅差值当作精确收益。

四组启动后的 metrics 报告 GPU 空余约 247–265 MiB；三项组合的启动日志明确警告 247 MiB 低于 512 MiB 安全余量，较满时驱动可能分页并使 decode 降到个位数 tok/s。测试前基线启动日志也报告约 265 MiB，所以低余量是现有基线配置的约束，并非本轮参数造成；新增的 16K prefill 在启动时还把页锁定缓存从基线 22.75 GiB 提高到约 28.76 GiB，组合最高约 30.12 GiB。

测试结束后已从备份恢复测试前配置，并确认 Strata 健康且 idle：模型仍为 IQ3，context 262144、15 workers、parallel 2、batch-groups 1、batch-mtp、hnorm stream、KV int8 / resident 32768、layer split auto；启动日志为 prompt chunk auto 8192 / 96-slot ring，aux-cpus 默认关闭。视觉仍关闭。正式 EvalScope 质量评测没有恢复。
