状态：completed；四组各 12 个请求全部成功，未发现前缀复用。模型为 SC117 IQ3_S + Q8 PLE，Strata 0.1.45，双 RTX 2080 Ti 分层推理，虚拟机 32 vCPU、128 GiB 内存，pool-workers=15。

C 组两个 guest NUMA 内存后端都设为 `hostnodes=0,policy=preferred`，A/B 保留虚拟机原内存策略。D 组设为 `hostnodes=0-1,policy=interleave`。C 的 node 0 占用已经达到最高，但 128 GiB 虚拟机无法全部放进容量约 128 GiB 的单个宿主节点，因此仍有约 15 GiB 回退到 node 1。D 的交错也没有达到 50/50，主要受 node 1 当时约 34 GiB 空闲容量限制。

## 解读

仅把 32 个 vCPU 固定到宿主 node 0 后，B 相对 A 的逐项 decode 中位比为 100.7%，64K 以上 prefill 中位比为 98.3%。这个变化不足以证明绑核带来稳定收益。

C 相对 A 的逐项 decode 中位比为 102.0%，64K 以上 prefill 中位比为 99.9%；D 分别为 101.0% 和 97.8%。

C 的六档简单 decode 相对 A 平均为 102.4%，逐档范围为 101.2%–103.4%；这部分提升很小，复杂任务和 prefill 没有同步变化，单次测试不足以证明它稳定可复现。

四组的 4K 简单 decode 约 141–145 tok/s；六档简单文本中位 126–129 tok/s，六档复杂文本中位 72–74 tok/s；240K 首 token 约 110–113 秒。组间差异与单个请求的 MTP 接受率和背景负载波动处于同一量级。这轮结果支持“当前推理路径对宿主 NUMA 亲和性不敏感”，但不支持把绑核作为当前主要优化项。

限制：每组每项只测一次，不能刻画长时间波动；测试未关闭宿主上的其他虚拟机，各组的空闲内存和实际页面落点因此不完全相同。C 是优先策略而非严格绑定，D 也没有达到理想 50/50，所以结果描述的是这些可实际执行的放置方式，不是理论上的满容量本地化对照。该测试也不能单独判断 IPC 或核心数对 Strata 的影响。

逐项数据见 `measurements.csv`，机器汇总见 `summary.json`，原始过程见 `sweep.json`，各组 EvalScope 数据库与报告保存在对应的 tar.gz 中。测试期间出现的 AER 均为`21:00.0` NVMe 的可纠正 RxErr，没有记录到处理器 MCE；这与之前已知的固态硬盘接口报错一致。测试结束后的一次恢复启动遇到 GPU VFIO 句柄短暂占用，在句柄释放后已重启成功，并复核虚拟机原配置、服务健康和配置文件哈希。
