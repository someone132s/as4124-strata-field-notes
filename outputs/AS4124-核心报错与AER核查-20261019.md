## 这些日志是用什么命令读出来的

核心错误由内核在启动时读取 ACPI BERT 表并解码，记录在内核 ring buffer 中。随后用
systemd journal 读取各次启动的内核日志：

```bash
# 列出可用的启动编号
journalctl --list-boots --no-pager

# 当前启动读取到的“上一次启动遗留错误”
journalctl -k -b 0 --no-pager -o short-iso

# 上一次启动自己的内核日志
journalctl -k -b -1 --no-pager -o short-iso

# 只截取 BERT 记录
journalctl -k -b 0 --no-pager -o short-iso |
  sed -n '/BERT: Error records from previous boot:/,/BERT: Total records found:/p'
journalctl -k -b -1 --no-pager -o short-iso |
  sed -n '/BERT: Error records from previous boot:/,/BERT: Total records found:/p'
```

实际采集脚本见 `work/collect_reboot_evidence_20261019.py`。其中 `-b 0` 是当前启动，
`-b -1` 是上一次启动。`dmesg` 只能读取当前启动的 ring buffer，无法读取历史崩溃启动，
所以这里使用 `journalctl`。

当前 AER 用下面两条读取：

```bash
journalctl -k -b --no-pager -o short-iso |
  grep 'nvme 0000:21:00.0: aer_status'
cat /sys/bus/pci/devices/0000:21:00.0/aer_dev_correctable
cat /sys/bus/pci/devices/0000:21:00.0/aer_dev_fatal
cat /sys/bus/pci/devices/0000:21:00.0/aer_dev_nonfatal
```

BMC 事件使用：

```bash
ipmitool sel elist
```

当前 BMC 时钟错误地停在 2026-04-28，而操作系统时间是 2026-10-19，因此不能用 BMC
时间线代替内核日志时间。SEL 中已有很多 `PCI PERR`，但没有找到明确的 CPU/cache
ProcessorError 记录；CPU 错误的主要证据仍是 BERT/MCE。

## 前部 NVMe 与 CPU1 的对应关系

Supermicro [`A+ Server AS-4124GS-TNR/TNR+ User's Manual`](https://www.supermicro.com/manuals/superserver/4U/MNL-2302.pdf)
（MNL-2302）第 13–14 页：

- 主板连接器 `P1-PCIE3A/B`、`P1-PCIE4A/B`、`P1-PCIE5A/B` 均列为
  “Processor 1 NVMe Ports”。
- `P2-PCIE6A/B` 至 `P2-PCIE10A/B` 才属于 Processor 2。

随机背板为 `BPN-SAS3-216A-N4`。其
[手册](https://www.supermicro.com/manuals/other/BPN-SAS3-216A-N4.pdf)第 2-3 页写明，`CPU_SEL0`、`CPU_SEL1`
默认均为 Open，此时：

```text
NVMe Drive Slots 1-4 connected to CPU 1
NVME #1 的 VPP 来自 CPU1
```

因此前部四个 hybrid NVMe 槽默认都连接到 CPU1。

当前 Linux 拓扑也一致：

```text
DapuStor NVMe: 0000:21:00.0
根端口:        0000:20:01.1
两者的 NUMA node: 0
```

即该 NVMe 的 PCIe 路径确实来自 CPU1（Linux socket 0）。AER 的
`aer_layer=Physical Layer`、`aer_agent=Receiver ID` 可能涉及 CPU1 的 PCIe
根复合体、P1 连接器、前部背板、NVMe 线缆或 SSD 本体的信号路径。

这台机器的 AER 在换 CPU 前的 2026-10-18 基线中已经存在，换 CPU 后仍持续出现。
因此它能进一步说明故障域落在与 CPU1 相连的 PCIe 路径，但不能单独证明是新换的
7452 CPU 本体导致。需要排查的对象应同时包含 CPU1、主板 P1 NVMe 接口、前部背板和
NVMe 本体。
