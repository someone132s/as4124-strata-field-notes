6. 功能验收（部署完必做）
短答确定性：3 则固定短答（法国首都→巴黎；2+3→5；“床前明月光”接句）全部正确
针召回：tools/needle_bench.py --lengths 1k,32k,64k,128k --depths 10,50,90（默认端口 8080，
注意改 --url）；参考结果 12/12。必须关思考（enable_thinking:false）且 max_tokens ≥ 40（默
认思考会吃掉 token，误判为召回失败）
长答口径：温度 0 下长答非逐字确定（本引擎既有现象，非故障）→ 判据 = 内容稳定且正确，不做逐字 diff
视觉（如启用）：生成含数字的 PNG → data URL 发送 → 比对数字（实测 4/4）
性能三点：32K / 128K / 230K prefill 与 decode 与 §7 参考值同量级
7. 性能基线与口径（参考机实测）
口径 A（客户端）：prefill ≈ prompt_tokens / 首字墙钟；decode e2e = 完成 token / 全程墙钟（含提示读
取，会低估 decode）
口径 B（引擎日志，推荐）：每请求一行 done: N tokens in T s (R tok/s) → R = 纯生成速率；读提示
耗时 ≈ T − N/R
参考数字（生产栈，262K，pw2，计数类请求 2600 生成 token）：
prefill：32K ≈ 1.72–1.76k · 128K ≈ 2.39k · 230K ≈ 2.39–2.45k tok/s
decode（gen-only）：32K ≈ 149 · 128K ≈ 142 · 230K ≈ 138 tok/s；同请求 e2e 口径 ≈ 87 / 90 / 80
decode 依任务形状浮动（草稿接受率相关，±10% 级）；测量须在空闲机上进行（单请求串行，多人用会
排队）
8. 已知坑（按踩坑优先级）
永不设置 CUDA_LAUNCH_BLOCKING=1：该变量本身会挂死 verify 窗口（上游已定性），也不能用它诊断崩溃
不要开 STRATA_STAGE_PIN：曾默认开启并损坏 IQ3_S 长读后的 decode；现为 opt-in，保持不设
262K 是风险档：上游同型机报告启动期 arena 耗尽（最坏冻结主机）→ 备 204800 档，冻结/启动 OOM 先
降档复测
构建：换版本先清 build/（CMakeCache 坑，见 §3）
前缀复用按 16384 块对齐：同文档 B 请求 ≤16K 不命中属正常，不是缓存故障；测试设计要按块对齐取点
短答必须关思考：否则 max_tokens 被思维链吃光，正文为空
冷启动首请求偶发挂起：服务端看门狗会自愈（v0.1.41 起为增强版：90s 无输出且无 CPU/IO/GPU 活动才终
止）；重启后建议先发一个小请求预热
单请求串行：多客户端请求交替排队、聚合吞吐不叠加（本配置非多槽 batch 模式）
9. 升级与回滚
上游会重写历史 → 一律 git fetch origin tag vX + git cherry-pick（跨版本 PR 不要 merge，会把
上游分叉整个拖进来）
升级流程：停服务 → 取码（如需再 cherry-pick 未合入 PR）→ 清 build/ + gcc-15 构建 → md5 + 
BUILD.json 守卫 → 起服务 → §6 功能验收 + §7 三点对照
