# 五款CPU比较与7452验证设计

日期2026-10-16；本轮只研究、未更改服务器或执行新性能负载。用户倾向先换一对7452，一无锁一锁总价750–850，假定旧两颗7282实际各成交320，则回款640、净差价110–210加运费。兼容组合必须卖家验证、到机复验；没有保证锁版副插槽可在本板运行。

## 硬件

7282：Rome/Zen2，16C32T，2.8/3.2GHz，L3 64MB，120W，四通道2667带宽优化，规格85.3GB/s每插槽。
7452：Rome/Zen2，32C64T，2.35/3.35GHz，L3 128MB，155W，完整8通道DDR4-3200规格204.8GB/s。
7443：Milan/Zen3，24C48T，2.85/4.0GHz，L3 128MB，200W，8通道DDR4-3200。
7R13：OEM Milan/Zen3，本次选48C96T型号条目；AWS平台标最高3.6GHz。不能混入PassMark另一个名称带64-Core条目。Supermicro H12DSi-N6裸机XMRig样本双路96C192T、L3总384MB，折每颗192MB；公开二手参数混杂，不默认256MB。完整频率/TDP需以实际OPN/BIOS核对。
7V13：OEM Milan/Zen3，64C128T；AMD研究集群实际使用双路7V13。H12DSi-N6裸机XMRig样本双路128C256T、L3总512MB，折每颗256MB。公开平台频率/TDP存在不同记载，PassMark记约2.5/3.7GHz与240W，PC2实际部署文档则记2.0/3.675GHz；不把其中任一套直接保证为用户所购料号。查到的额定功耗不作已确认规格。

## 7452如何验证核心扩展收益

保留原相同8条、每路4通道；先测内存读写复制和延迟（原硬件基线已存在，必要时同环境重测），分清更换CPU后带宽是否恢复。更多核心不等于更多已安装内存通道，不承诺7452原四条能达到8通道204.8。

Strata先固定原两张2080Ti的UUID，排除新2070S（现GPU0是2070S）。固定模型文件/PLE、版本、MTP参数、KV、实际输入、输出、缓存策略、并发、GPU功耗及层分配。分别记录prefill/TTFT/decode、MTP接受率、专家缓存命中、频率与实际NUMA页分配。

同一7452上只分配单socket物理核，RAM绑同socket，先8/16/24/32核（不含SMT兄弟）或先16对32再细化；worker数围绕有效物理核心设置并考虑主线程，不能只改worker不限制CPU亲和性。先观察单socket32对16；后续才测跨双socket64，后者同时增加NUMA和通信变量。保留相近CCD分布、记录频率；不能以限16核宣称完整模拟7282，因为缓存/拓扑/内存状态不同。

如果7452限16核比旧7282大幅提高，说明增至32核不是该段改善的必要条件，但仍不能将改善全部归于DRAM，缓存/频率/训练/拓扑也变了。同一7452由16到32核继续显著提高，才是增加可用核心在当前负载有边际收益的直接证据；32无增益则更多核心不优先。必须同样请求重复、平衡顺序，不能以某次decode过100作为核心扩展证据。

## 直接相关的独立Strata案例

新找到的第一方自测文章：https://lcz.me/topic/2116/3 。作者7R13 48C、256GB八通道、4x3090，比较多路径并使用自定义fork。自述47worker约19.55tok/s，限制线程后78–92；最后单3090/12worker。不能视为受控的仅worker单变量结论（有引擎/路径变化），但足以说明100+不能按核心数推断。文章32K custom一次107、长测32K Cold中位91.1，前缀命中中位118.1；运行路径/缓存影响很大。不是用户硬件实测，且不保证可靠复现。

## 决策

7452为低净成本诊断+VM容量提升桥梁；7443为更强单线程/中等核数候选；7R13/7V13为核心扩展确实有效且预算明确后再评估的吞吐方案。即使7452满32核无增益，也不能证明7443无效（架构/单线程不同）。即使7452由16到32有增益，也不能线性外推到7V13的64核。核对锁版+无锁组合并不保证修复低带宽。
