# 内存带宽规范复核与 R730 对照（2026-10-15）

AS4124 宿主的低带宽在标准 STREAM 和独立 LIKWID 汇编读取内核中重复出现。R730 同版本纯读取单路约 13–15 GB/s、双路约 26 GB/s；GPUServer-1 的双虚拟节点访问未能叠加带宽。根因尚未确定，不能据此给出纯虚拟化损耗百分比，或直接认定 DIMM、CPU、超频故障。

## 测法与可复现条件

- 标准 STREAM 分别报告 Copy/Scale/Add/Triad。每个数组至少为参与末级缓存总和的四倍；Copy/Scale 是读写混合的逻辑流量，不能称为纯读取。[STREAM 作者规则](https://www.cs.virginia.edu/stream/ref.html)
- 独立交叉验证使用 LIKWID-bench `load_avx`，没有浮点归约和写回。工具负责线程绑定与内存放置，速率也是程序可见流量。[作者文档](https://github.com/RRZE-HPC/likwid/wiki/Likwid-Bench)
- 对照主表全部使用 **LIKWID 5.2.2、同一个二进制及配套库**。另保留 5.4.1 的初测，不混入主表。
- 每工作组 1,536,000,000 字节（1536 MB，十进制）；双路使用两个独立工作组，共 3.072 GB，各自并行首次触碰本地页。每次固定16遍，独立进程重复三次，报告中位数与范围。
- 单路16个物理核心，双路各16个，共32个；不选 SMT 兄弟。R730 有20物理核心/路，此处为与 EPYC 对照，只选16个。其物理 CPU 编号按奇偶分属两路，不能照搬 AS4124 的连续编号。
- AS4124/R730：`likwid-bench -t load_avx -i 16 -W S0:1536MB:16:1:2`；节点1改S1，双路加第二个 `-W S1:1536MB:16:1:2`。
- 虚拟机未暴露SMT，使用 `S0:1536MB:16` / `S1:1536MB:16`，不加`:1:2`。这些是虚拟节点本地页；不等同于宿主物理本地页。
- 原始输出逐一验证全部 worker 的 CPU 编号；首遍另采样 `/proc` 的线程 affinity 和 NUMA 页位置。17/33线程含一个辅助线程。保存子进程CPU时间和主缺页数，超时90秒。
- 测试顺序为宿主后虚拟机，宿主与其虚拟机的带宽负载不重叠。R730 是另一台物理机。其他VM保持运行，没有清缓存、关闭swap、修改BIOS或CPU/VM内存配置；Strata保持原模型与参数。
- 工具用 Debian 官方发行包解包到测试目录，未安装系统服务、未启动 LIKWID access daemon、未配置PMU或MSR。两种发行版依赖不同，最终用 Debian12 构建的5.2.2套件统一三台机器。

单位均为十进制 GB/s；三次中位数。

## 硬件与内存频率

AS4124 / H12DSG-O-CPU：双 EPYC7282，8×32GB，每CPU四条。SMBIOS逐条报告 `Speed: 2933 MT/s`、`Configured Memory Speed: 3200 MT/s`。这与用户在BIOS手动设为3200一致，可以确认固件报告配置为3200；尚未取得独立的内存控制器实时频率读数。这不是3200MHz，DDR3200对应3200MT/s。

AMD官方将7282列为8内存通道、最高3200MT/s、**每插槽85.3GB/s**；它不是物理只有四个通道的CPU。实际四通道×3200×8字节的裸接口算式为102.4GB/s，官方85.3GB/s条目本身不能证明所有频率和布局下的精确硬限速，亦不能把理论值当STREAM保证值。[AMD规格](https://www.amd.com/en/support/downloads/drivers.html/processors/epyc/epyc-7002-series/amd-epyc-7282.html)

R730：双E5-2698v4、40物理核心/80逻辑线程、4×32GB，安装在A1/A2/B1/B2，每CPU两条；SMBIOS的标称与配置值均为**2133MT/s**。按每路两个独立64bit通道计算的裸接口上限为34.128GB/s/路，双路68.256GB/s。它不是四通道满配的E5平台。

## STREAM 与其他复核

AS4124绕过自写绑定wrapper，直接用numactl运行原版STREAM，16线程分别绑定节点0的16个物理核心，Copy约7.68GB/s、Triad约5.52GB/s，校验通过。没有支持“wrapper导致所有线程挤在同一核心”的证据。

另一个公共AVX2（x86-64-v3）构建使用GCC14、静态OpenMP、`STREAM_ARRAY_SIZE=80000000`、`NTIMES=10`，每数组640MB。AS4124节点0 Copy约7.70、Triad约5.41GB/s；R730使用同一二进制，节点0三次中位Copy约10.71、Triad约10.21GB/s，节点1Copy约10.72、Triad约9.86GB/s。均校验通过。该构建同时改变了数组大小与编译目标，只能说换另一种构建后低值依旧，不能当成单变量数组对齐实验。

STREAM公共构建SHA256：`0533408be1f6c12114b41620e37349385d1b36b738045cb13d64a05144d3cb52`。旧znver2构建不用于R730。

## 重要限制及解释

1. AS4124共同版本9次主缺页均为0，读取结果约7.1–7.7GB/s/路、14.2GB/s双路；前一轮5.4.1结果相近。低值确实跨工具重复，值得继续查宿主，但尚未找出根因。
2. R730同版本节点0第一次有1个主缺页，其他8次为0。早先5.4.1双路约17GB/s，后续共同版本约26GB/s；追加5.4.1/5.2.2交替测试后两者均约25–26GB/s，因此不能把早先低值归因于版本。未控制的后台负载等因素仍可能影响结果，保留全部记录。
3. GPUServer-1共同版本双节点三次主缺页为24/0/21，单节点均为0。主缺页包含进程启动/库加载等，不能直接断定测试数组被换出；也不能描述为全程无缺页。测试后MemAvailable约54GiB、历史swap约454MiB、PSI内存均为0，不能仅凭swap存量认定内存不足。之前自己的纯读约7.86GB/s默认配置，与本轮8.20GB/s双节点处于接近量级。
4. 虚拟机vCPU允许在宿主两路间调度，没有物理核固定绑定。虚拟NUMA页位置不证明宿主物理页位置。旧的宿主QEMU页分布及测试后vCPU快照仅供拓扑线索，不能用于计算纯hypervisor开销。
5. 读取带宽、STREAM带宽与Strata速度不是同一个指标。当前证据支持优先排查宿主内存访问与VM放置，但尚不能认定这是Strata prefill差距的全部原因，亦不足以推荐更换CPU。

本轮到此停止负载，未自动切换模型或启动后续引擎测试。
